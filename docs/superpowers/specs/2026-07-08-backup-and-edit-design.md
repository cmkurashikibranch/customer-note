## ① バックアップ

### UI（設定画面に「💾 データを守る」カードを追加）

```
┌──────────────────────────────┐
│ 💾 データを守る                │
│ [📤 バックアップを保存]        │
│ [📥 バックアップから戻す]      │
│ 最終バックアップ：2026-07-08   │←未実施なら「まだありません」
└──────────────────────────────┘
```

既存の「AI読み取り」カードの下に置く。

### 書き出し（保存）

1. 書き出す中身は **customers・nextId・settings のうち followUpDays のみ**（AI設定3項目と lastBackup は含めない）。封筒形式で包む：
   ```json
   { "app": "customer-note", "version": 1, "exportedAt": "2026-07-08",
     "data": { "customers": [...], "nextId": 12, "settings": { "followUpDays": 14 } } }
   ```
2. ファイル名：`お客様ノート_バックアップ_YYYY-MM-DD.json`（実機確認項目：LINE等へ共有した際のファイル名化けの有無）
3. 出し方（フォールバック順）：
   - `navigator.canShare({files})` が真 → 共有シート（LINEで自分に送る・Googleドライブ等）
   - 共有シートを**キャンセル**（AbortError）→ 何もしない（lastBackupも更新しない）
   - 共有シートが**それ以外のエラー**（iOS SafariのNotAllowedError/TypeError等）→ ダウンロード方式に自動フォールバック
   - 共有API非対応 → `<a download>` によるファイルダウンロード
4. 成功時：`settings.lastBackup = todayStr()` を保存して表示更新。
   - 共有経由：「✅ 保存しました」
   - ダウンロード経由：「✅ 保存しました（『ファイル』アプリの『ダウンロード』にあります）」

### 読み込み（戻す）＝「弾く」＋「補う」の2段

1. `<input type="file" accept=".json,application/json">` でファイル選択。処理後は `input.value = ''`（同じファイルの再選択に備える）。FileReader の `onerror` は「ファイルを読めませんでした」
2. **弾く（純関数 `validateBackup(text)`）**：
   - JSONとして読めるか／`app === 'customer-note'` か／`data.customers` が配列か
   - 各customerに `id`（数値）と `name`（文字列）があるか
   - `version > 1` →「新しい版のバックアップです。アプリを更新してください」で拒否
   - 不合格 → `null` を返し「このファイルは読み込めませんでした。バックアップファイルか確認してください」
3. **補う（純関数 `normalizeBackup(data, currentSettings)`）**：クラッシュ防止のため必ず通す
   - `lastContact` 欠落 → `exportedAt`（無ければ今日）で補完／`history` 非配列 → `[]`
   - `settings` → DEFAULT_DATA.settings とマージし、**AI設定3項目は現端末の値を維持**
   - `nextId` → `Math.max(0, ...ids) + 1` 未満なら補正（空配列でも安全な形）
4. **事前バックアップ提案**：`lastBackup` が今日でなければ「先に今のデータをバックアップ保存しますか？」→ はい＝書き出しを実行してから続行
5. **確認ダイアログ（具体的に）**：「**2026-06-20に保存した**ファイル（5件）で、今の20件を置き換えます。**15件減ります**。よろしいですか？」（増える場合は「◯件になります」）
6. 置き換え → `saveData()`。失敗時は元のデータに戻して警告。成功なら「✅ ◯件を復元しました」→ ホーム再描画

### リマインド（ホーム画面）

- 表示条件：`customers.length >= 1` かつ（`lastBackup` 未設定 or `daysSince(lastBackup) >= 14`）かつ 今日スヌーズされていない
- 表示：検索欄の下に「💾 そろそろバックアップしませんか？（タップで設定へ）」の薄い枠＋右端に「×」
- ×：`settings.reminderSnoozedOn = todayStr()` でその日だけ非表示（翌日再表示）
- バックアップ保存に成功したら消える

## ② 編集機能

### UI

- 詳細画面の「✅ 連絡した」の上に「✏️ 編集」ボタン（ghost系）を追加
- 押すと登録画面（view-register）を**編集モード**で開く：
  - 見出し「お客様情報を編集」／保存ボタン「変更を保存」（新規時は「お客様を登録」「保存する」に**必ず戻す**）
  - 写真・名前・会社・電話・メールに現在値をプリセット。写真は撮り直し可
  - **隠すもの**：OCR貼り付け（details）・🤖AIボタン・メモ欄
- 保存 → 該当customerを更新 → `renderDetail()` と `renderHome()` の両方 → 詳細画面に戻る
- 「← もどる」→ 編集モードなら詳細画面へ・新規モードならホームへ（分岐）

### 実装方針（状態管理の穴を塞ぐ）

- グローバル `editingId = null`（登録モード）/ `customerId`（編集モード）
- **フォームリセットの条件**：①編集モードから新規モードに切り替わるとき ②保存成功後、の2つだけ。**新規→新規は下書き温存**（登録途中に「もどる」で一覧を見て戻っても入力が残る現行挙動を守る）
- **photo changeリスナー**：AIボタン表示は `editingId === null` のときだけ（編集中に写真を替えてもAIボタンは出さない）
- **関数ガード**：`runParse` / `runAiRead` / `clearPaste` は編集モード中は動作しない（UIを隠すだけでなく関数冒頭でもガード）
- `saveCustomer()` の分岐：編集モードなら該当customerの5項目（photo含む）を上書き。`lastContact`・`history` は触らない。保存失敗（容量）時は変更前の値に戻す。名前必須チェックは共通

## エラー処理まとめ

| 場面 | ふるまい |
|------|---------|
| 共有シートをキャンセル | 何もしない（エラー扱いしない） |
| 共有シートがエラー（キャンセル以外） | ダウンロード方式に自動切替 |
| バックアップファイルが壊れている・別アプリのもの | 「読み込めませんでした」表示・データは無傷 |
| 新しいversionのファイル | 「アプリを更新してください」で拒否 |
| 復元後の保存で容量超過 | 元のデータに戻して警告 |
| 編集保存で容量超過 | 変更前の値に戻して警告 |
| ファイル読み取り自体の失敗（FileReader onerror） | 「ファイルを読めませんでした」 |
